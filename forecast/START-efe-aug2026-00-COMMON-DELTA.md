## 1. 확정 교정 규칙 (7월 배치 산출, 이번 배치에 반드시 반영)

### R1. op_margin 앵커 = **연결 GAAP OP 마진** (세그먼트/adj EBITDA 아님)
- 근거: GEV 2026Q2 — adj EBITDA +61%·마진 +340bps인데 GAAP EPS는 미스. 세그EBITDA→연결GAAP 웨지(상각·D&A·적자세그·본사비)가 통째로 빠졌다.
- 형태: **shape = 과거 8~9Q 계절 벡터**, **level = 직전 분기 actual 또는 회사 가이던스**.
- **⚠️ 이번 배치 반전 경고**: GEV/TSLA는 앵커가 *과대*여서 하향이 답이었다. **SNDK·AMD는 정반대 — 과거평균 앵커는 심각한 과소예측을 낸다**(SNDK 매출 YoY +343%). 규칙의 본질은 "하향"이 아니라 **"과거평균 금지, level은 최신 actual/가이던스"**다. 이 문장을 FROZEN에 인용하고 방향을 명시할 것.

### R2. below-OP 블록은 **앵커 금지 · base 0 · 광폭 밴드**
- 근거: TSLA OI&E가 −$380M(Q1)→**+$590M**(Q2)로 부호 반전. SK하이닉스는 below-OP 밴드 실패 **3회 재발**(키옥시아 지분법 40조). GEV는 이자+비영업연금 +1.7%.
- 규칙: FX·평가손익·지분법·일회성·워런트는 **base 0**, 밴드로만 표현. 과거 평균으로 앵커링하지 말 것.
- **SNDK는 Kioxia JV 지분법**, **SPCX는 이자비용 $1.9B/yr + 리스**, **AMD는 워런트/투자평가손익**이 각각 이 항목이다.

### R3. 세율은 **단일 앵커 금지 · 범위 시나리오**
- 근거: GEV 유효세율 22% 가정 vs actual **29.8%**(PPA 조정 + 세금혜택 없는 지역손실). 콜의 "higher taxes" 발언은 현금흐름 설명이지 P&L 세율 근거가 아니다.
- 규칙: bear/base/bull에 **서로 다른 유효세율**을 넣고, 그 폭의 근거(밸류에이션 얼라운스·지역믹스·FDII·일회성)를 적는다.

### R4. 비-12월 결산 / 계절 이슈어는 `backtest_methodology.revenue_growth_qoq` **필수**
- 근거: `project_scenario`(forward)는 positional, `backtest_generic`은 캘린더 슬롯 소비 → 한 벡터가 두 규약을 동시에 만족 못 한다. 픽스 후 GEV backtest 매출 MAPE 20.3%→2.93%.
- **이번 배치 해당: SNDK(6월 결산, FY26 Q4)**. 나머지 3종은 12월 결산이지만 계절성이 강하면 동일 적용(VST 여름 피크).
- 커밋 전 forward 출력을 `rev × (1+g)` 손계산으로 반드시 대조.

### R5. GAAP ↔ adjusted **브릿지 계약** (신설, 이번 배치 필수)
EFE generic이 산출하는 것은 **GAAP**다. 그런데 컨센서스는 종목마다 기준이 다르다.
- AMD·SNDK 컨센 = **non-GAAP/adjusted EPS**, VST 컨센·가이던스 = **adjusted EBITDA/adj FCF**, SPCX = **적자라 EPS 무의미**.
- 규칙: FROZEN (a)에 **GAAP 값과 컨센 기준 값을 둘 다** 제시하고, 그 사이 **브릿지를 항목화**(SBC · 인수 무형자산 상각 · 분사/구조조정 · 파생 MTM · 워런트). 브릿지를 못 세우면 (d) 컨센 대비 위치는 **"비교 불가"로 명시**하고 억지로 숫자를 맞추지 말 것.
- 사후 채점도 **같은 기준끼리** 비교한다. 기준 혼용은 채점 무효.

### R6. 사후 채점 표기 표준
- 4-lever generic 귀인(매출 / 영업이익률 / OP→NI / 주식수), **잔차 0 확인**. 5-lever 메모리 버전 재사용 금지.
- 컨센 서프라이즈는 **`HIT` / `MISS` / `NO_SURPRISE`** 3값으로 명시.
- **밴드 폭을 정량 기록**한다. 7월 배치는 밴드 커버리지 3/3이었지만, 밴드가 넓어서 맞은 것과 좁게 맞춘 것은 다르다 — `밴드폭 ÷ base` 를 남겨 다음 분기에 캘리브레이션한다.
- 스킬 게이트 미달이어도 **동결·채점을 회피하지 않는다**. 헤더에 `LOW_SKILL` 표기.

### R7. 원문 인용 계약 (`00-COMMON.md` §7) 그대로 적용
- 7항(출처식별·분량·추출기·섹션앵커·수치좌표·항등식검증·표 시각확인) 미충족 수치는 **동결 근거로 쓰지 않는다**.
- 샌드박스는 `www.sec.gov`/`data.sec.gov`가 프로세스 레벨 403 → **WebFetch 도구로만** EDGAR 접근 가능(markdown 변환본이라 바이트 SHA 불가). SHA-256은 "호스트 필요"로 명시하고 나머지 6항을 채운다.
- 발표 당일 actual은 companyfacts가 수일 지연 → **보도자료/8-K/IR 딱지**로 대체하고 `actual_source_stage`를 기록.

```
   "리스크밴드로 보낼 구조적 항목"인지 판정
§6 Codex 6축 질의 (아래 그대로 복사해 붙일 것)
```

**§6에 넣을 6축 질의 템플릿:**
1. **정확성** — 내가 계산한 4-lever 귀인이 잔차 0인가? 항등식(`OP + below-OP = 세전`, `세전 − 세금 = 순이익`, `귀속순익 ÷ 희석주식수 ≈ EPS`)이 원문 수치로 성립하는가?
2. **건전성** — 앵커(op_margin·세율·below-OP·주식수)의 근거가 표본기간과 함께 명시됐나? 사후지식(발표 후 정보)이 동결 논리에 새어 들어가지 않았나?
3. **회귀안전** — 이 변경이 `scripts/verify_9q_sha.py`의 SK하이닉스 9Q sha256을 bit-identical로 유지하는가? 기존 5종 forward 출력이 불변인가?
4. **범위규율** — 요청 범위 밖 리팩터가 섞이지 않았나? 인접 코드는 `NOTICED BUT NOT TOUCHING`으로만 기록됐나?
5. **검증가능성** — 제안된 개선이 실패하는 테스트로 표현 가능한가? 새 테스트가 추가됐나?
6. **유지보수성** — 종목 고유 하드코딩이 generic 경로에 침투하지 않았나? 프로파일 YAML로 표현됐나?

**루프 규율(7월 배치에서 실제로 문제였던 것):**
- Codex의 "diff 0 / pytest 통과 / NUL clean" 주장을 **믿지 말고 독립 재현**하라. 여러 건이 사실과 달랐다.
- git(add/commit/push)은 **호스트/Codex 전담**. 샌드박스 git read는 `GIT_OPTIONAL_LOCKS=0` 접두.
- 대형 `.md` 편집은 컨테이너 마운트 stale/truncation 이력 → **device_bash `>>` heredoc으로 디바이스에 직접 append**가 안전. 편집 후 `ast.parse`(py) / `wc -l` / NUL 스캔.
- 프로파일·스크립트 쓰기는 **원자적(temp→replace) + 직후 재read fail-closed**.
