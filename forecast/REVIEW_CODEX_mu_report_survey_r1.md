## 2. ➕ 사양

### 2.1 표지 시장 데이터 박스 - ed1

1. 넣을 절: 표지 핵심 수치표 옆의 작은 `Market data / 시장 데이터` 블록.
2. 데이터 출처: 기존 manifest fact인 기준 주가, 최신 공시 발행주식수, 계산 시가총액, 회계연도 종료일만 사용한다. 거래량·52주 범위·유동비율은 제외한다.
3. allowlist·SHA: 새 외부 입력 없음. 가격 2경로와 post-print 공시는 기존 E2-B 예약 입력·전체 SHA 핀을 그대로 쓴다.
4. 입력 게이트: 기존 E2-B 4개 입력 게이트 중 가격 2경로와 A-8K/EX-99.1 충족 후 생성한다.
5. 게이트·UNAVAILABLE: G-3e·G-14·G-15·G-16·G-17·G-20 적용. 어느 구성 fact가 없으면 해당 셀만 `UNAVAILABLE`이며 추정하거나 다른 날짜 값을 대입하지 않는다.

### 2.2 보조 P/B - ed2

1. 넣을 절: §9 밸류에이션의 보조 역사 행. 목표가 계산에는 연결하지 않는다.
2. 데이터 출처: 가격은 기준일 CITED fact, 장부가치는 공시 자본과 공시 시점 발행주식수다. RLE 기간 P/B는 자사주·자본 roll-forward가 없으므로 만들지 않는다.
3. allowlist·SHA: ed1 기준가·A-8K의 기존 핀을 재사용한다. ed2에서는 10-K 원본 SHA가 추가된다. 새 입력이 필요하면 §4-7에 정확 경로·전체 SHA를 먼저 추가한다.
4. 입력 게이트: ed2 10-K 게이트 통과, 자본·발행주식수·기준일이 모두 확인돼야 한다.
5. 게이트·UNAVAILABLE: G-3b·G-14·G-15·G-16·G-17·G-20. 분자·분모 기준일이 다르면 두 날짜를 캡션에 병기한다. 장부가치 또는 주식수 누락 시 `UNAVAILABLE`.

### 2.3 역사적 P/E·P/B 밴드 - ed2

1. 넣을 절: §9, 기존 암시 배수 표 뒤의 보조 차트 2개 이내.
2. 데이터 출처: 분할 조정 일별 종가와 당시 공시된 TTM GAAP EPS·주당장부가치. 미래 추정치와 제3자 컨센서스는 쓰지 않는다.
3. allowlist·SHA: `logs/mu_report_history_price_<start>_<end>.<ext>`와 필요한 SEC 공시 원본을 §4-7 ed2 행으로 추가하고 전체 SHA를 핀한다. 다운로드 출처·조회일·조정 방식도 source_id에 고정한다.
4. 입력 게이트: 전 기간 가격·분할 이력·공시 분모가 재현 가능하고, 보고일 이후 데이터가 0건이어야 한다. 그렇지 않으면 차트 전체를 만들지 않는다.
5. 게이트·UNAVAILABLE: G-1·G-3·G-13b·G-14·G-15·G-16·G-17·G-20·G-21. 적자 기간 P/E는 `N/M`; 보간·윈저라이징 금지. 핀 입력이 없으면 `UNAVAILABLE` 설명 한 줄로 대체한다.

### 2.4 공시 실제치 기반 피어 비교 - ed2

1. 넣을 절: §9의 별도 `Peer operating and trailing valuation context` 표. 상세 계약은 §3을 따른다.

3. allowlist·SHA: 피어별 공시 원본, 가격 캡처 2경로, 공식 환율 파일을 `logs/mu_peer_<ticker>_<period>_*` 고정 경로로 받고 §4-7 ed2 행에 전체 SHA를 핀한다.

2. 데이터 출처: 최종 렌더 PDF 자체에서 계산한 생성물 메타데이터.
3. allowlist·SHA: 새 외부 입력 없음. 생성물 재검증 읽기 규칙을 사용한다.
4. 입력 게이트: 최종 PDF 생성 후 G-21 렌더 검사를 시작하기 전에 계산한다.
5. 게이트·UNAVAILABLE: G-12b·G-15·G-18·G-21. PDF 페이지 수를 다시 열어 푸터·manifest와 일치시킨다. 불일치는 발행 실패이며 `UNAVAILABLE` 대체는 허용하지 않는다.

### 2.7 목차 - ed1

1. 넣을 절: 표지 다음 1쪽. KO/EN 동일 위치·동일 절 순서.
2. 데이터 출처: 렌더러의 절 id·제목·최종 페이지 번호. 외부 fact가 아니다.
3. allowlist·SHA: 새 외부 입력 없음. i18n 템플릿과 렌더 코드의 Git blob SHA만 감사 기록에 남긴다.
4. 입력 게이트: 12개 본문 절이 모두 생성되고 최종 페이지 나눔이 확정돼야 한다.
5. 게이트·UNAVAILABLE: G-15·G-18·G-21. 모든 앵커와 쪽수를 역검증한다. 불일치는 발행 실패이며 빈 목차나 `UNAVAILABLE`은 허용하지 않는다.

## 3. J-1 피어 비교 설계

### 3.1 범위와 선정 규칙

1. 1차 피어는 최근 회계연도 매출의 과반이 메모리 반도체(DRAM·NAND·HBM)에서 발생하고, 규제 공시로 실제치 3표와 주식수를 재현할 수 있는 상장사로 한정한다.
2. 후보는 SK hynix와 SanDisk다. Samsung Electronics는 메모리 세그먼트 영업 지표에는 포함할 수 있지만, 전사 시가총액을 메모리 세그먼트 분모와 섞는 오류를 막기 위해 메모리 세그먼트 배수 행에서는 제외한다. 분리 가능한 공시 실제치만 운영 비교 열에 둔다.
3. 최종 포함은 이름이 아니라 위 규칙과 입력 완비 여부로 결정한다. 조건 미충족 후보를 억지로 채우지 않는다.
4. 피어 추정치·컨센서스·목표가·리서치사 조정치는 전부 금지한다.

### 3.2 표 지표

- 식별: 회사, 티커, 공시 기간 종료일, 회계연도 주수, 회계기준, 보고통화.
- 운영 실제치: 매출, GAAP/해당 회계기준 영업이익, 영업이익률, 순이익, 재고, 재고일수(동일 식으로 계산 가능할 때), capex, 영업CF, FCF.
- 시장·배수: 같은 기준일 시가총액, EV, trailing P/E, P/B, EV/EBITDA, EV/Sales, FCF yield.
- 분모가 비양수면 `N/M`; 세그먼트와 전사 범위가 일치하지 않으면 `UNAVAILABLE_FOR_COMPARISON`.

### 3.3 입력·기준일·통화·회계기준

1. 공시: SEC 10-K/10-Q, DART/회사 사업보고서 등 규제 원문만 사용하고 경로·전체 SHA·원문 좌표를 기록한다.
2. 가격: MU와 피어 모두 2026-10-01 각 상장시장 정규장 종가. 휴장 시 임의 전일 대체하지 않고 Jiwon 결정으로 올린다. 각 가격은 2경로 캡처를 요구한다.
3. 기간: 기준일 당시 공개된 최신 TTM을 사용한다. 회사 간 종료일 차이가 120일을 넘으면 유량 지표의 횡비교를 `UNAVAILABLE_FOR_COMPARISON`으로 둔다. 정확 기간은 셀·캡션에 병기한다.
4. 통화: 배수는 원통화에서 계산한다. 절대액을 한 통화로 보여줄 때만 동일 기준일 공식 환율을 사용하고 원통화도 함께 보존한다.
5. 회계: US GAAP와 K-IFRS를 임의 정상화하지 않는다. 회사 정의와 회계기준을 표시한다. EBITDA·FCF는 보고서의 §4-5·§4-3 식으로 재계산할 수 있을 때만 비교한다.

### 3.4 게이트

- 기존 G-1·G-3·G-14·G-15·G-16·G-17·G-20·G-21을 전부 적용한다.
- 신규 `G-22 peer-actual-only`: 모든 피어 숫자가 공시 실제치 또는 그 lineage 계산인지, 추정·컨센서스·목표가 필드가 0개인지, 가격일·기간 종료일·통화·회계기준이 명시됐는지, 배수 분자·분모 범위가 일치하는지 검사한다.
- 신규 `G-22b peer-period-alignment`: TTM 종료일 차이 120일 초과 셀이 비교 가능 값으로 렌더되면 실패한다.

### 3.5 §7 개정 문안

> 경쟁사 병렬 예측·가치평가 모델링은 금지한다. 단, 피어의 규제 공시 실제치와 동일 기준일 시장가격만 사용한 운영·trailing 배수 비교표는 허용한다. 피어 추정치·컨센서스·목표가·리서치사 조정치는 금지한다. 회사별 기간 종료일·회계연도 주수·보고통화·회계기준·가격 기준일을 표시하고, 범위 또는 기간 정렬이 불가능한 셀은 `UNAVAILABLE_FOR_COMPARISON`, 비양수 분모는 `N/M`으로 둔다. 세그먼트 실제치와 전사 시가총액을 섞지 않는다.

## 4. J-2 고지 설계

### 4.1 고정 키와 문안

- 키: `disclaimer.conflict`
- 한국어: `발행 직전 확인 시각({{conflict.confirmed_at_kst}}) 현재, 작성자 김지원은 Micron Technology, Inc. (MU) 주식을 보유하지 않습니다.`
- 영어: `As of the pre-publication confirmation time ({{conflict.confirmed_at_kst}}), the author, Jiwon Kim, does not hold shares of Micron Technology, Inc. (MU).`
- 푸터 축약 키: `disclaimer.conflict_short`
- 한국어 축약: `작성자 MU 주식 미보유 - 발행 직전 재확인.`
- 영어 축약: `Author does not hold MU shares - reconfirmed before publication.`

### 4.2 발행 직전 재확인

1. ed1·ed2마다 별도 confirmation YAML을 Jiwon이 확인한다.
2. `confirmed_at_kst`는 렌더 시작 전 24시간 이내이고 `edition`이 빌드 대상과 같아야 한다.
3. 빌더는 확인 레코드의 blob SHA와 읽은 시각을 input manifest·실행 로그에 남긴다.
4. 상태가 `not_held`가 아니거나 확인이 없으면 렌더를 중단한다. 보유 상태 변화 시 자동 문구 추정 없이 Jiwon에게 새 문안을 승인받는다.
5. KO/EN 본문과 PDF 푸터가 같은 확인 레코드를 참조하는지 G-15와 G-12c로 검사한다.

## 5. ❓ 대안

1. 작성자 연락처: 공개 동의된 연락처가 없으므로 작성자명만 유지한다. 향후 Jiwon이 공개용 주소를 명시적으로 제공하면 고정 문자열이 아니라 승인된 설정값으로 추가한다.
2. 콜 핵심 문답: Q&A 원문을 확보하기 전에는 준비문과 공시된 경영진 발언만 `Prepared remarks / 준비문`으로 표시한다. Q&A처럼 재구성하지 않는다.
3. 업계 재고: 회사 공시 재고·재고일수와 경영진의 정성적 업계 코멘트를 분리해 표시한다. 업계 재고 수치를 제3자 차트에서 전사하거나 추정하지 않는다.
4. 컨센서스 수정 이력: 현재 확보된 시계열 원본이 없으므로 삭제한다. FQ4는 SCORED의 허용된 스냅샷만, FY27은 `UNAVAILABLE_FOR_COMPARISON`만 유지한다.
