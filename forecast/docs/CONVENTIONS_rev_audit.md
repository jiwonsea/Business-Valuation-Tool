## §1. rev 갱신·감사 규약 (P-5)

검증자(Codex) 지적으로 해시 고정 문서를 갱신할 때, 다음 5단계를 순서대로 수행한다:

1. **원본 보존:** 갱신 전 현행본을 `<파일명>_revN_superseded.md` 로 복사 (이후 무수정·무삭제).
2. **생성기 수정 → 동일 파일명 덮어쓰기:** 문서를 직접 고치지 않는다 — 생성 스크립트를 고쳐
   같은 파일명으로 재생성한다 (손타이핑 0 유지).
3. **매니페스트 supersede 기록:** append-only 부록에 rev-N→rev-N+1 사유·정정 항목·감사 사본
   해시(파일에서 계산)를 기록. 기존 매니페스트는 무수정.
4. **핸드오프 §0 정정 이력 표:** 지적 → 반영 위치 → 상태(이전 rev 에서 확인 완료 / 본 rev 검증
   대상)를 항목별로 표기.
5. **diff 국한성 검증 요청:** 직전 superseded 사본과 현행본의 diff 가 해당 정정(및 rev 라벨·이력
   표기)에만 국한됨을 검증자가 기계 확인하도록 요청. 재계산 수치는 동일 모듈 재실행으로 불변임을
   병기.

효과 (실증): 정정 1건당 1왕복으로 수렴하고, 검증자가 "그 외 무변경"을 diff 로 기계 확인할 수 있다.

## §2. 크로스 환경 재생성 게이트 (P-8)

해시 고정 대상 산출물(보고서·핸드오프·매니페스트·동결 후보)은 다음을 **완료 조건**으로 한다
(관행 → 규약으로 승격):

- **샌드박스 ×2:** `LC_ALL=C PYTHONIOENCODING=ascii python3 <생성기>` 2회 — sha256 동일.
- **디바이스 ×1 이상:** 동일 명령으로 재생성 — 샌드박스와 **비트 동일**.
- **CRLF 0** (LF 전용) · NUL 없음.
- 생성물은 cwd 에 떨어지므로 **격리/작업 디렉터리에서 실행**하고, 동결 디렉터리 직접 실행은 금지.
  재생성 strays 는 해시로 중복 확인 후 `_to_delete/` 로 이동 (마운트 unlink 불가).

이 게이트가 실제로 잡은 결함: 디바이스 python(<3.12) f-string 백슬래시 SyntaxError ·
Windows CRLF 오염 · cp949 콘솔 크래시. 신규 생성기 공통 요건: `open(..., newline="\n")`,
콘솔 출력은 VERBOSE 옵트인 + `errors="replace"`, 최종 sha256 라인은 ASCII 전용,
f-string 표현식 안에 백슬래시 금지.
